# Verifying an install

Copy-paste checks, boot package first, desktop package second. Run each on
its own line — some need `sudo` and some don't, and mixing them into one
pasted block can silently skip the ones that do.

## Boot chain (`omarchy-plymouth-nier`)

```bash
cat /usr/share/omarchy-plymouth-nier/built-for
```
First line: this machine's resolution. If it says a resolution that isn't
yours, the artwork was never regenerated for this panel — run
`sudo omarchy-nier-reconfigure` with the build tools installed (`python`,
`imagemagick`, `fontconfig`, `noto-fonts-cjk`, `ttf-jetbrains-mono-nerd`).
Second line: a config fingerprint — useful for confirming two machines are
running the exact same settings, not meaningful on its own.

```bash
pacman -Qkk omarchy-plymouth-nier
```
`0 altered files`, unless you've run `omarchy-nier-reconfigure` — that
regenerates the package's own theme files in place, which this command
correctly (if noisily) reports as "altered". Not a bug.

```bash
sudo grep -c '>>> omarchy-nier' /boot/limine.conf
```
`1`. This is the marker around the spliced-in menu config block.

```bash
plymouth-set-default-theme
```
`omarchy-minimal`.

```bash
cat /etc/plymouth/plymouthd.conf
```
Must include `DeviceScale=1` — without it, Plymouth's HiDPI heuristic
upscales every image 2x on a >96 DPI panel and blurs the whole screen. See
[README.md, point 2](README.md#five-things-that-will-bite-you).

The Limine menu is the one screen you can actually preview without
rebooting — see [tools/README.md](tools/README.md). The LUKS prompt and the
shutdown screen only render pre-login and pre-shutdown; there's no way to see
them from a running session, and **don't try starting `plymouthd` to check** —
it grabs the console and can leave you with no working keyboard.

## Desktop themes (`omarchy-nier-themes`)

```bash
omarchy-nier-themes status
```
Expect:
```
  package themes         /usr/share/omarchy-nier-themes/themes
  nier-black             symlink -> /usr/share/omarchy-nier-themes/themes/nier-black
  flexoki-light-alt      symlink -> /usr/share/omarchy-nier-themes/themes/flexoki-light-alt
  hook dark-browser-chrome installed
  hook gtk-colors        installed
  gtk.css                installed (GTK4/libadwaita follows the palette)
```
If a theme shows `a real directory is already there` instead of a symlink,
nothing is broken — the linker refused to touch a pre-existing directory
rather than overwrite it. `omarchy-nier-themes link --force` moves it aside
and links properly; see [INSTALL.md § Troubleshooting](INSTALL.md#troubleshooting).

```bash
omarchy theme list | grep -i -E "nier|flexoki light alt"
```
Both should be listed.

```bash
gsettings get org.gnome.desktop.interface icon-theme
```
`'Yaru-wartybrown'`, once one of the two themes is active.

```bash
head -1 ~/.config/gtk-4.0/gtk.css
```
Should start with a comment naming the active theme and
`generated by build-gtk.py`. If the file doesn't exist, re-apply the theme —
`omarchy theme set` is what triggers the hook that installs it:

```bash
omarchy theme set "Nier Black"
```

Open the file manager (Nautilus) and check it visually — sidebar, background
and folder icons should follow the theme's palette, not stock GNOME blue.
This only applies to GTK4/libadwaita apps and only takes effect on the next
window you open; a window already open when you switch themes keeps its old
colours until reopened.

## Both installed together

```bash
pacman -Q omarchy-plymouth-nier omarchy-nier-themes
```
Two lines, no errors.
